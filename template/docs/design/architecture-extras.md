## 典型场景（详细版）：游戏对话总结

这是 DoorX 展示 AI 能力的典型场景，也可复用于会议录音、播客转录、教程笔记等。

│  ┌─────────────────────────────────────────────────────────────────┐   │

### 数据模型（示例）

```go
// 游戏对话会话
type GameChatSession struct {
    ID              string
    GameName        string
    StartTime       int64
    EndTime         int64
    Speakers        []SpeakerProfile
    Transcripts     []TranscriptSegment
    Summaries       []SummarySegment
    Status          SessionStatus
}

type SpeakerProfile struct {
    ID              string
    VoiceprintID    string
    UserLabel       string
    Color           string
    FirstSeen       int64
    MessageCount    int
}

type TranscriptSegment struct {
    ID              string
    SpeakerID       string
    Content         string
    StartTime       float64
    EndTime         float64
    Confidence      float64
}

type SummarySegment struct {
    ID              string
    Type            SummaryType
    Content         string
    KeyPoints       []string
    Timestamp       int64
}

type SummaryType string
const (
    SummaryTypePeriodic  SummaryType = "periodic"
    SummaryTypeFinal     SummaryType = "final"
    SummaryTypeHighlight SummaryType = "highlight"
)
```

### 技术实现要点

1. **声纹识别**
   - 第三方服务（如 AssemblyAI、Deepgram）或本地模型（Silero、SpeechBrain）
   - 生成唯一说话者指纹

2. **语音分离**
   - Speaker Diarization（说话人分离）
   - 实时处理 vs 事后处理（权衡延迟和准确性）

3. **上下文监控**
   - Electron: `nativeMessage` 或 Node addon
   - Windows: Win32 API 检测活动窗口
   - macOS: Accessibility API
   - 音频捕获：系统音频设备

4. **隐私保护**
   - 用户明确同意才录音
   - 数据加密存储
   - 提供一键删除功能

## 典型场景（详细版）：长视频整理 + 字幕翻译

### 流程概览

```
视频上传/录入
    ↓
抽取音频 → ASR 转写 → 分段校对
    ↓
内容整理/摘要 → 关键段落标注
    ↓
字幕翻译（多语言）
    ↓
产物输出（SRT/VTT/Markdown/JSON）
```

### Action 组合示例

1) `video_ingest`：视频入库与元数据解析  
2) `audio_extract`：抽取音频  
3) `asr_transcribe`：语音识别转写  
4) `content_summarize`：长内容整理/摘要  
5) `subtitle_translate`：字幕翻译  
6) `artifact_publish`：产物打包与回写

### 交互要点

- 用户选择执行位置：本地 / 云端 / 指定节点
- 长任务显示进度、预计耗时、取消与重试
- 产物自动写回云端并同步到本地

### 执行节点上的最佳实践（无现成服务的独立服务器）

**目标**：独立服务器“只需运行执行节点”，即可完成视频→音频→转写→翻译→产物落盘的全链路。

推荐方案：

1) **执行节点自带最小运行时**  
   - 依赖：`ffmpeg`、ASR 引擎（本地或外部服务客户端）、翻译模型或 LLM 客户端  
   - 只运行 runner，不运行主库/控制面

2) **数据就近处理（优先级最高）**  
   - 如果视频已在该服务器磁盘上：Action 直接使用 `node://path` 作为输入  
   - 如果视频在云端：先上传/落到对象存储，再由执行节点拉取（避免从客户端回传大文件）

3) **Action 输入/输出约定**  
   - 输入：`inputRef` 支持 `node://`（本地路径）或 `s3://`（对象存储）  
   - 输出：`outputDir` 相对工作目录，禁止任意绝对路径（避免越权写入）  
   - 产物：字幕 `*.srt/*.vtt`、摘要 `*.md`、结构化 `*.json`

4) **结果回写策略**  
   - 小产物直接回写云端主库（文本/元数据）  
   - 大产物存对象存储，仅回写引用（URL/ETag）

**示例执行流程（节点本地已有视频文件）**：

```
Cloud Router → 指定 node_id
    ↓
Node 拉取任务描述（含 inputRef=node://videos/foo.mp4）
    ↓
ffmpeg 抽取音频 → ASR 转写 → 翻译 → 汇总
    ↓
产物落盘到 node://videos/foo_subtitle.srt
    ↓
回写云端：字幕/摘要/索引（或对象存储 URL）
```

**示例任务描述（简化）**：

```json
{
  "action": "video_subtitle_translate",
  "target": "cloud@node_id",
  "inputRef": "node:///data/videos/foo.mp4",
  "outputDir": "outputs/foo/",
  "artifacts": ["subtitle.srt", "summary.md", "transcript.json"]
}
```

更完整的交互与缺口分析见：`docs/design/scenarios/execution-node-video-processing.md`。
